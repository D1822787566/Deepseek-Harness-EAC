# 项目定义 — Deepseek Harness EAC（内网 / 本地模型优先版）

> 状态：**草案 v0.1 · 2026-08-20 · 待评审**
> 本文是「项目新定义」的唯一权威来源。定稿后 README 措辞将随本定义同步更新。
> 相关执行规则（Agent 硬规则）见仓库根 `AGENTS.md`。

---

## 1. 一句话定义

**Deepseek Harness EAC = 可部署到内网、连接本地 OpenAI 兼容模型的 AI Agent 桌面客户端。**

在保留官方 `@deepseek-ai/dsh`「一切皆插件」架构与 EAC 全部桌面能力的前提下，
把模型请求链从「云端 DeepSeek API」切换到「内网本地模型端点」，让整个产品在
**不接入外部网络**的环境里开箱即用、数据不出内网。

## 2. 背景与动机（为什么重新定义）

- **原定位**：面向个人开发者的在线桌面客户端——依赖云端 API、GitHub Releases 更新、在线插件市场。
- **新场景**：私有化部署。企业/团队在内网或隔离网（air-gapped）环境中使用 AI Agent 工作台，
  要求：
  1. 模型请求只发往**本地模型服务**（不出内网）；
  2. 安装部署**不依赖外部网络**（自带运行时与全部依赖）；
  3. 会话、配置、凭证、日志全部**本地留存**。
- **决策（2026-08-20）**：保留「Deepseek Harness EAC」名字，重新定位；不做品牌重塑。
  模型层契约统一为 **OpenAI 兼容端点**（覆盖 vLLM / Ollama / LM Studio / Xinference / 私有化 DeepSeek 等）。

## 3. 核心原则（In scope 的边界）

| 原则 | 含义 |
| --- | --- |
| 本地模型优先 | 模型请求默认指向本地/内网 OpenAI 兼容端点（base URL 可配，apiKey 可空，模型列表可配） |
| 离线可用 | 双击即用、零外网依赖是底线能力；安装包自带 node.exe + npm CLI + dsh 全家桶（已具备，不得破坏） |
| 数据不出内网 | 会话/配置/凭证/日志全部本地留存；不新增任何未经评审的上报 |
| 保留 EAC 既有能力 | 皮肤、内置插件、终端、文件追踪、人设卡、插件保护中心等全部保留；内网化是叠加定位，不是砍功能 |
| 一切皆插件不变 | 不 fork 核心架构；改动尽量落在壳层配置与内置插件，保持 dsh 上游可升级 |

## 4. 目标用户与核心场景

1. **内网办公环境**：无法访问公网的开发/业务团队，用本地模型完成编码、文档、知识问答。
2. **数据敏感场景**：代码、文档、对话内容不允许出内网的组织。
3. **离线便携**：无网环境（生产网、隔离网）仍需完整 AI Agent 工作台。

## 5. 能力范围

### In scope（本定义覆盖）

- 模型层：OpenAI 兼容端点接入（配置 UI + 运行时）
- 桌面层：既有的全部 EAC 能力（皮肤/插件/终端/文件/人设/保护中心…）
- 部署层：离线安装包分发、数据本地留存、DSH_HOME 隔离
- 配置层：可视化配置本地端点与模型列表

### Out of scope（本定义不覆盖 / 保持可选）

- `openclaw-dsh-bridge`（微信 ClawBot 桥接）：保持独立可选子工程，不并入内网版主链路
- `research/` 调研资料：只读参考
- 在线插件市场、云端账号体系、余额服务：外呼能力，按 §7 策略处置（默认收敛）

## 6. 技术架构约束（改造不越界的红线）

```
Electron 壳 (main.js) ──spawn 内置 node.exe──▶ dsh web (127.0.0.1:<port>)
                                                   │
                                      provider 配置的 base URL
                                                   ▼
                                   本地/内网 OpenAI 兼容端点（vLLM / Ollama / LM Studio / Xinference …）
```

1. 保持「Electron 壳 + 本地 dsh web（仅回环）」架构不变。
2. 模型接入 = 配置 provider 的 base URL 指向本地端点；凭证本地存储（沿用 `.credentials.yaml`）。
3. 不 fork `@deepseek-ai/dsh` 核心；改动落在 `dsh-desktop` 壳层与 `assets/plugins/` 内置插件。
4. 原生模块（sharp / node-pty / koffi）由内置 node.exe 加载，`asar:false` / `npmRebuild:false` 不变。
5. 新增外呼必须登记并评审（见 AGENTS.md §5.1 与下文 §7）。

## 8. 演进路线（草案，随 §7 定案调整）

- **P0 · 模型层切本地（先行）**
  - 验证并文档化「provider 指向本地 OpenAI 兼容端点」的最小可用路径
  - easy-setup / 设置页提供本地端点配置入口与模型列表
  - 首次启动引导（无外网时的配置向导）
- **P1 · 网络边界收敛**
  - 更新器/市场/余额/遥测按 §7 定案处置（默认关闭或移除）
  - 全仓外呼点审计清单落地（AGENTS.md §5.1 已列骨架）
- **P2 · 内网分发**
  - 离线安装包（内置全部依赖，无需联网安装）
  - 内网源/镜像、签名、版本管理策略

## 9. 验收口径（定义是否达成的检查）

1. 一台**无外网**的干净 Windows 机器，双击安装包可启动、可配置本地模型、可完成一轮对话。
2. 默认配置下，除模型请求发往本地端点外，**无任何外部网络连接**（可用抓包/防火墙验证）。
3. 既有 EAC 桌面能力（皮肤/插件/终端/文件追踪等）不回归。
4. `@deepseek-ai/dsh` 核心可继续随上游升级（架构未 fork）。
